## 14. 组合 stair: 40s + 每个 waypoint 8s 奖励/终止

只改组合 `stair`（5 个 waypoint），`stair_up` / `stair_down` 仍是 15s。

### 总时长

```python
cfg.episode_length_s = 40.0
```

5 个 waypoint × 8s = 40s。

### 独立奖励函数

`config/reward/Trackingreward.py` 新增：

```python
stair_waypoint_track_target(
    window_s=8.0,
    reward_window_s=2.0,
    ...
)
```

逻辑：

- 计时从当前 waypoint 激活开始（reset 或上一个 waypoint 到达）。
- 前 `8 - 2 = 6s` 返回 0。
- 最后 2s 返回与 `track_target_position` 相同的 `1 / (1 + dist²)`。
- 奖励是连续 per-step 值，不是最后 2s 一次性给。
- 到达下一个 waypoint 后，计时清零，重新给新 waypoint 8s。

组合 stair 用新 term 替换原来的 `track_target_position`：

```python
cfg.rewards.pop("track_target_position", None)
cfg.rewards["stair_waypoint_track"] = RewardTermCfg(
    func=stair_waypoint_track_target,
    weight=2.0,
    params={
        "command_name": "Goal_direction",
        "window_s": 8.0,
        "reward_window_s": 2.0,
        "foot_body_names": ("FR_foot", "FL_foot", "RR_foot", "RL_foot"),
        "height_command_name": "Base_height_target",
    },
)
```

同时把 `track_target_bias` 的时间门控设为 40s，使航向对齐奖励在
40s episode 内全程可用（仍受 2m 距离门控）。

### 超时终止

`config/reward/Trackingreward.py` 新增：

```python
stair_waypoint_timeout(window_s=8.0)
```

逻辑：

- 当前 waypoint 从激活开始超过 8s 仍未到达 -> 返回 True。
- 截止步会检查一次 `reach_target`；刚好在 8s 到达也算按时，不会误终止。
- 作为失败终止注册，`time_out=False`。
- 到达 G5 后 `stair_waypoint_completed=True`，不再触发该终止；
  episode 继续到 40s 总超时。

```python
cfg.terminations["stair_waypoint_timeout"] = TerminationTermCfg(
    func=stair_waypoint_timeout,
    time_out=False,
    params={"window_s": 8.0},
)
```

### 状态变量

`reset_stair_waypoints` 初始化：

```python
env.stair_waypoint_start_time[env_ids] = 0.0
```

`update_stair_waypoints` 在切换到下一个 waypoint 时：

```python
env.stair_waypoint_start_time[ids] = (
    env.episode_length_buf[ids].float() * env.step_dt
)
```

验证：

- t=5.9s 奖励为 0，t=6.0~7.98s 奖励激活，t=8.0s 奖励关闭。
- t=7.9s 不终止，t=8.0s 未完成 -> 终止。
- 完成 G5 后 8s 终止不再触发。

## 15. stair 前向速度惩罚

只加在 stair_up / stair_down / stair 三个任务，其他地形不变。

函数：`config/reward/Trackingreward.py`

```python
stair_forward_speed_penalty(
    command_name="Goal_direction",
    desired_speed=0.8,
    speed_deadzone=0.3,
    goal_deadzone=0.35,
    foot_body_names=(...),
)
```

逻辑：

```text
v_forward = base_xy_velocity · direction(foot_center -> current_goal)
speed_error = |v_forward - desired_speed|
x = max(speed_error - speed_deadzone, 0)
penalty = x^2
distance_foot_center_to_goal < goal_deadzone -> penalty = 0
```

配置：

```python
cfg.rewards["stair_speed_tracking"] = RewardTermCfg(
    func=stair_forward_speed_penalty,
    weight=-0.1,
    params={
        "command_name": "Goal_direction",
        "desired_speed": 0.8,
        "speed_deadzone": 0.3,
        "goal_deadzone": 0.35,
        "foot_body_names": ("FR_foot", "FL_foot", "RR_foot", "RL_foot"),
    },
)
```

数值示例（`v_desired=0.8`，`v_forward=0`）：

```text
speed_error = 0.8
x = 0.5
penalty = 0.25
raw reward = -0.1 * 0.25 = -0.025
per second = -0.025
```

这是一个温和的 nudge，不会主导其他奖励。终点 0.35m 内关闭，允许停车。

验证：

- stair_up / stair_down / stair 都有 `stair_speed_tracking`，weight `-0.1`。
- flat 等其他地形没有该 term。
- 距目标 0.2m 时 penalty=0；距目标 2m 且前向速度 0 时 penalty=0.25。

## 17. 三个 stair 的课程上限改为 level 5

适用：

```text
stair_up
stair_down
stair
```

在 `_make_stair_env_cfg()` 中设置：

```python
cfg.curriculum["terrain_levels"].params["max_level"] = 5
cfg.curriculum["terrain_levels"].params["randomize_at_max"] = True
```

行为：

- 课程从 level 0 正常逐级升到 level 5；
- 通过 level 5 后不再升到 6/7/8/9；
- 到达上限后，reset 时在 `0 ~ 5` 之间随机难度；
- 如果随机到较低的 level，会继续按课程往上练，回到 level 5 后再次随机。

验证：

```text
up / down / combined:
  max_level = 5
  randomize_at_max = True
```

模拟通过 level 5 后连续 reset，采样到的等级都在 0~5：

```text
[[1,3,0,2], [2,4,5,4], [0,4,1,2], [2,1,4,3], ...]
```
