## 1. 地形

文件：`config/terrain/stair_terrain.py`

### stair_up

- 正金字塔，原点从“顶平台”改到“底面平面” `z=0`。
- 8m 金字塔外增加 2m 平坦外圈，整体 patch 变成 12m。
- 金字塔本身的尺寸、级数和难度不变。
- 这样 5m 出生点在 patch 内，不会踩到相邻地形行的台阶。
- 出生点距最低台阶 2m。

### stair_down

- 倒金字塔保持原样，原点在底部中心。
- 出生点在凹底中心附近。

### stair（组合）

布局（西 → 东）：

```text
3m 出生平台 | up 正金字塔 | 1m 平地 | down 倒金字塔
```

- up 底面和 down 顶面都在 `z=0`。
- 组合 patch 尺寸 `18m × 8m`。
- up 中心在 env 局部 `x=-2`，down 中心在 `x=+5`。
- 出生点在 env 局部 `x=-7`，距 up 最低台阶 2m。
- 组合地形用同一个 difficulty 同时生成 up 和 down，所以难度 0 就是两侧都平。

## 2. 5 个目标点

文件：`config/event/stair_waypoint.py`

env 局部坐标：

```text
G1 = (-2.0, 0)   up 顶中心
G2 = ( 1.3, 0)   up 东侧底部（1m 平地内）
G3 = ( 1.7, 0)   down 西侧顶部（1m 平地内）
G4 = ( 5.0, 0)   down 底部中心
G5 = ( 8.5, 0)   down 东侧顶部
```

规则：

- reset 时目标设为 G1。
- 到达当前目标后，自动切到下一个目标。
- 到达 G5 后目标停在 G5，episode 继续到超时。
- 每个目标的到达判定复用 `reach_target`：四足中心 XY + `Base_height_target` 高度。
- 阈值 `0.15m`。

## 3. 目标高度

`config/command/AllTrackingCommand.py`

`HeightTargetCommand` 增加：

- `ground_z_min`：默认 `0.0`，保留旧地形行为。
- `set_ground_z_override()`：允许 waypoint 事件把目标高度固定到指定值。

组合 stair 的 waypoint 高度：

```text
G1 = +H
G2 =  0
G3 =  0
G4 = -H
G5 =  0
```

其中 `H = (num_steps + 1) * step_height`，按当前地形难度实时计算。

组合 stair 的 `ground_z_min=None`，允许 down 坑底出现负高度；up / down 仍跟随足端动态估计地面高度。

## 11. Viser 地形难度切换修复

问题：Viser 的 `Terrain Difficulty (地形难度)` 下拉框只写入
`env.specified_terrain_level` 并请求 `RESET`，但新的 up / combined reset
函数没有消费这个值，所以切换后仍停在原难度。

修复：

- `config/event/stair_reset.py` 提取 `sync_specified_terrain_level()`。
- `reset_root_state_from_stair()` 改为调用该函数。
- `reset_root_state_at_stair_base_sides()`（up）和
  `reset_root_state_west_of_stair()`（combined）在写 root state 前调用该函数。
- 同步内容：
  - `terrain.terrain_levels[env_ids]`
  - `env.scene.env_origins[env_ids]`
- 支持：
  - 固定等级 `0 ~ num_rows-1`
  - `"random"` / `-1` 随机等级
  - `STAIR_LEVEL` / `TERRAIN_LEVEL` 环境变量

同时把下拉框的台阶高度标签改为按地形实际 `step_height_range` 计算，
level 9 显示 `0.30m steps`，不再是固定的 `0.27m`。

验证：在组合 stair 中设置 `specified_terrain_level=7` 后 reset，
`terrain_levels` 变为 7，`env_origins` 切到第 7 行，`Base_height_target`
同步变为 `1.4m + 0.28m`；up / down 切到 level 9 也正常。

## 13. teacher / student 观测噪声策略

按“教师特权观测不加噪，学生部署观测加噪”统一：

```text
teacher actor    corruption=False   特权观测，干净输入
teacher critic   corruption=False
teacher rnd      corruption=False

student actor    corruption=True    部署观测，训练时加噪
student critic   corruption=False
student rnd      corruption=False
```

实际创建环境后检查 observation manager：

```text
teacher actor : noisy_terms=[]
teacher critic: noisy_terms=[]
teacher rnd   : noisy_terms=[]

student actor : noisy_terms=['base_ang_vel', 'projected_gravity',
                             'joint_pos', 'joint_vel', 'height_scan']
student critic: noisy_terms=[]
student rnd   : noisy_terms=[]
```

这样教师 PPO 训练和蒸馏时教师模型看到的输入都是无噪声的，学生 actor 仍保留
部署时的观测噪声。观测维度不变。
